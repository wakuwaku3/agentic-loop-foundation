Nothing on this page starts a Provider CLI or probes anything. Every value is derived from observations the Loop's own execution path produced, so a Provider a human drove by hand outside the Loop is invisible here and is shown as unknown — an absence of observation, never a fault. Whether the owner has authorised a Provider and whether the Loop has ever completed an invocation through it are shown as two separate facts, because today they disagree for two of the three. A stale observation is shown with its age and keeps the value it was last observed to have; it is never refreshed and never downgraded silently. Reaching a runaway-detection threshold is a stop for inspection — neither a success nor a failure — and this page can only report it: clearing one needs a new owner-approved record. The threshold numbers are deliberately not shown here; the approved record that declares them is named instead.
