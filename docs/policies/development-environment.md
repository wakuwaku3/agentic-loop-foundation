# 開発環境ポリシー

## 目的

このポリシーは、[外部環境コード化ポリシー](external-environment.md)を開発・検証環境へ具体化する下位ポリシーである。開発者の端末やCI runnerの環境差によるテスト結果の変動を防ぎ、同じソースから同じ検証環境を再現できる状態を維持するため、すべての変更に適用する。上位ポリシーと要件が重なる場合は、より厳しい要件を満たす。

## コード化と固定

開発、ビルド、lint、テストに必要なOS相当のパッケージ、言語runtime、パッケージ管理ツールその他の実行依存は、リポジトリ内の宣言的な環境定義に記述し、lock fileまたは改変不能なdigestで固定する。ホストへ暗黙に導入されたツールへ依存してはならない。

このリポジトリの環境定義は `devbox.json` と `devbox.lock` とする。サポート対象はDevboxが動作する `x86_64-linux` と `aarch64-linux` であり、`devbox run --pure check` をローカルとCIの共通検証入口とする。`--pure` によりホストの環境変数を原則として検証へ持ち込まない。Devboxは環境を実現するためのbootstrap要件であり、検証に使うツール群はDevboxのlock fileで固定する。Devboxが内部的に使うNixを開発者やCIの公開入口として直接操作しない。

## 変更管理

実行依存を追加、削除または更新するときは、環境定義とlock fileを同じ変更に含め、採用理由と費用ポリシーへの適合を確認する。lock fileを意図せず更新してはならない。この変更管理は通常のPull Requestレビューで足り、worker自身の判断による事前承認の取得（人間の追加承認フロー）を必要としない。`devbox.lock`を含む環境定義ファイルの意図した更新自体を理由に、承認を要する変更だと自己判断してはならない。

環境定義には、サポート対象のプラットフォーム、利用手順、および環境内で実行されていることを機械的に検出できる印を含める。CIで環境定義から環境を構築し、リポジトリ共通の検証入口を実行する。

## 例外

既存プロジェクトへAgentic Loopを導入する場合は、そのプロジェクトのコード化済み環境を維持してよい。ただし、環境が未定義または依存が未固定であれば、そのプロジェクトに適した再現可能な環境定義を追加するまで変更を完了としてはならない。

緊急対応などで固定環境を利用できない場合は、理由、代替検証、環境差、および残るリスクを変更記録に明記し、固定環境によるCI成功前にマージしてはならない。
