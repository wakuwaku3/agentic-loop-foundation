# 外部環境コード化ポリシー

## 目的

このポリシーは、システムが依存または操作する外部環境を、担当者の記憶や手作業だけに依存せず再現、検証、復旧および移行できる状態に保つため、すべての変更と運用に適用する。外部環境の変更はアプリケーションコードの変更と同じ品質基準で管理する。

## 対象範囲

対象には次を含むが、これらに限らない。

- 開発端末とCI runnerを含む開発・検証環境
- GitHub Repositoryの設定、branch protection、ruleset、Label、WebhookおよびGitHub Projects
- CI workflow、runner、artifact、cacheその他の継続的インテグレーション基盤
- 将来のデプロイ先、network、DNS、compute、storage、database、監視その他の実行基盤
- user、team、service account、roleその他の権限と、秘密情報の保管・参照・rotation境界

## 必須管理情報

外部環境ごとに、次の情報をリポジトリ内の宣言的なコード、固定された設定、検証scriptまたは文書で管理する。

1. 識別子、所有者、目的、依存関係を含むdesired state
2. 冪等な作成・更新手段と、安全な適用順序
3. 現在状態との差分を検出するdrift検出手段
4. 適用後に要求を満たすことを確認する検証手段
5. backup、rollback、再作成、復旧および別環境への移行に必要な情報と手順
6. 破棄対象の特定、依存関係の確認、承認、backup、検証を含む安全な破棄手順

version、provider、actionその他の外部依存は、利用可能な場合はlock fileまたは改変不能なdigestで固定する。環境定義と適用・検証手段は同じ変更で更新し、レビューとCIの対象にする。費用、データ損失、可用性またはsecurityに影響する差分は適用前に明示し、破壊的・不可逆または重大なコストを伴う変更には利用者の明示的承認を得る。

## コード化できない設定

APIや自動化手段が提供されない設定も、未管理の手作業として黙認しない。制約、desired state、正確な手動手順、必要権限、実施証跡、drift検出、再検証、復旧および移行方法をコードまたは文書で管理する。可能な範囲をread-onlyの検査scriptで自動検証し、自動化手段が利用可能になった時点でコード化する。

## 権限と秘密情報

最小権限を使用し、適用主体、承認者および検証主体の責務を記録する。秘密情報の値をリポジトリ、log、Issue、Pull Request、artifactまたは環境定義へ保存してはならない。コード化するのは秘密情報の名前、参照先、必要権限、供給方法、rotation・失効・復旧手順であり、値は承認された外部の秘密保管境界から実行時に取得する。

## driftと変更管理

CIでは外部へ変更を加えず、定義の妥当性、固定、secret混入、適用計画またはfakeに対する呼び出しを検証する。実環境のdrift検出は原則read-onlyかつ再実行可能にし、検出結果、検査時刻、対象revisionおよび再検証方法を追跡可能にする。driftを自動修復する場合も費用ポリシーと承認条件を満たし、予期しない削除や権限拡大を行ってはならない。

## 例外と破棄

緊急対応その他の理由で一時的に要件を満たせない場合は、理由、影響範囲、代替検証、残るリスク、責任者、有効期限および解消条件を変更記録に残す。無期限の例外は認めず、期限までにコード化または再承認する。

環境の破棄は、保持義務、依存先、復旧可能性、費用およびsecurityへの影響を事前に検証する。破壊的または不可逆な操作は明示的承認なしに実行せず、実施後は対象が消去され依存先が正常であることを検証する。

## 開発環境との関係

[開発環境ポリシー](development-environment.md)は、このポリシーを開発・検証環境へ具体化する下位ポリシーである。`devbox.json` と `devbox.lock` による固定、`devbox run --pure check` の共通入口、対応platformおよび例外条件は引き続き必須であり、このポリシーによって弱められない。
